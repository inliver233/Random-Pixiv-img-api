# Review: RAPI-0224（最终全面自检）

时间：2026-02-03  
分支：`test`

## 1) Review 范围（按风险优先级）

- 路由兼容性：legacy Pixivcat 兼容路由（`/:illustId.:ext`、`/:illustId-:page.:ext`）不回归
- 随机图片 API：`/random`（image/json/redirect）与强筛选语义
- 稳定图片：`/i/:id.:ext`（长缓存、流式代理、heal 触发）
- 后台：`/admin`（鉴权、IP allowlist、CSRF、写限流、审计视图）
- 可观测：结构化日志、`request_id`、Prometheus `/metrics`
- 运维与部署：Dockerfile/Compose、迁移（Prisma migrate deploy）、反代（`trust proxy`）
- 安全：`npm audit` 已知残留项与缓解建议

## 2) 结论摘要

- 代码与文档以“不破坏 legacy”为第一原则：流式代理仍然不读入内存；稳定图片长缓存保持；`/random` 强制 `no-store`。
- 生产部署建议：推荐 Docker Compose + overlay；首次/升级先执行 `migrate` one-off 迁移，再启动/重启 backend。
- 反代场景必须设置：`TRUST_PROXY=1`，否则 IP 相关逻辑（限流、后台 allowlist）会出现安全/功能风险。

## 3) 已知风险（需要部署侧配合）

- `npm audit` 残留：`tinymce <7`（Moderate，Admin 侧依赖链）。缓解：
  - `/admin` 保持内网/allowlist，不对公网开放
  - 只给可信人员访问后台
  - 关注 AdminJS upstream 依赖更新后再升级验证
