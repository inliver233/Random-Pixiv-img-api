## 1. 关键阻断结论（High）

### 1.1 Admin 导入 jobs 全部进入 DLQ（Invalid import_id）→ Image=0 → /random 永远 NO_MATCH

现象链路（闭环失败）：
- Dashboard 明确提示 Image=0（导入次数=52），且 `/random` 成功率 0%。
  - 证据截图：`docs/review/screenshots/2026-02-10_18-39-57/admin-dashboard-image0-import52.png`
- `Import` 资源存在 52 条导入记录，但全部 `Success=0`（只记录了解析失败的少量 Failed）。
  - 证据截图：`docs/review/screenshots/2026-02-10_18-39-57/admin-import-list-success0.png`
- `Admin Jobs` 页面显示 `admin_images_import__dlq` 中大量 job，错误统一为 `Invalid import_id`，并附堆栈指向 `dist/src/jobs/importImages.js`。
  - 证据截图：`docs/review/screenshots/2026-02-10_18-39-57/admin-jobs-dlq-invalid-import-id.png`
  - 证据（DLQ sample + stack）：`docs/review/network/2026-02-10_18-39-57/admin-adminJobs-dlq-sample.json`

复现步骤（可复制）：
1) 登录后台（`/admin/login`，使用已配置的 session 账号；凭据略）
2) 打开 `/admin/pages/importUrls`，提交任意一批 pximg 原图 URL（建议小样本 10 行先验收）
3) 打开 `/admin/resources/Import`，观察该 import 的 `Success` 长时间为 0
4) 打开 `/admin/pages/adminJobs`，切换队列到 `admin_images_import__dlq`，可见同一批导入对应的 DLQ job（错误 `Invalid import_id`）
5) 打开 `/admin`，仍显示 `Image=0`；访问 `/random` 返回 `No matching image.`

根因定位（代码级）：
- **pg-boss 的 worker handler 入参是 `jobs` 数组**，而本项目的 `admin_images_import` / `admin_import_rollback` / `admin_pixiv_token_test_refresh` / `admin_proxy_endpoint_probe` 的 worker 以“单 job 对象”解析，导致 `job.data` 为空 → `import_id` 解析失败 → job fail → 进入 DLQ。
  - 线上堆栈：`/app/dist/src/jobs/importImages.js:281`（见 sample json）
  - 对应源码：`src/jobs/importImages.ts`（`registerAdminImportWorker` 内 `boss.work(..., async (job) => ...)`）
  - pg-boss 证据：`node_modules/pg-boss/dist/manager.js` 调用 `callback(jobs)`（handler 永远收到数组）

修复建议（可执行）：
- 统一将上述 workers 改为处理 `jobs` 数组：
  - 推荐：改用 `src/queue/queue.ts` 的 `work()` 封装（本项目其它 job 已按数组语义实现），或直接将 `boss.work(..., async (jobs) => { for (const job of jobs) ... })`
- 同步增加单测：验证 worker 在 pg-boss “array handler” 语义下可正确处理（最小：import job 能写入 images 并更新 Import.success）
- 发布后回归：
  - 在 `/admin/pages/adminJobs` 对 `admin_images_import__dlq` 执行「重试」抽样 3 个 job，确认 Import.success 增长、Image>0、`/random` 命中
